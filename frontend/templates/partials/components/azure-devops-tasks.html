{# Azure DevOps work-items widget. The shell is server-rendered (icon + title + filters + list skeleton); the rows are fetched client-side from GET /api/dashboard/ado-items. Keeping the fetch client-side lets us render pin/seen state without round-tripping to ui.py, while HTMX still owns the reload — now driven by the scheduler in portal-chrome.html rather than by a hardcoded 60-second poll. Scope: the list used to be every work item ever assigned to you, which read as a pile of unrelated tasks. It is now scoped to a sprint — by default the project's CURRENT iteration — and filterable by work item type. The type list comes from the project's process (Agile / Scrum / CMMI / custom all define different types), so it is fetched per project rather than hard-coded. The server-side `error` branch is still used for the ADO PAT-missing flow, because that requires the PAT capture form. #}
