{# The one dialog every action on another system goes through: review or comment on a pull request, run a pipeline again, create, move, describe, comment on or assign a work item (api/ado_actions.py), and create or add to a Confluence page (api/confluence_actions.py). A kind may name its own system and API; Azure DevOps is the default. A target may carry a DRAFT -- the text, the state, the vote DevBot proposed -- which fills the form, and the person can change any of it before anything is checked or sent. When an action completes it dispatches "portal:action-done" with the result (and, when something really changed, "portal:ado-changed", which the widgets refresh on); a dialog closed without completing dispatches "portal:action-closed". So whatever opened it -- a widget, DevBot -- knows how it ended. THREE STEPS, ALWAYS 1. Compose -- choose the vote, the state, the words. 2. Check -- Azure DevOps is asked first (dry_run): is the pull request still open, has the run finished, would the move be accepted. The person reads exactly what will happen, in their name, and confirms. 3. Result -- what Azure DevOps shows NOW, read back, with a link to it. Included once, from banner.html, so every page that shows a widget has it: window.portalAdo.open(kind, target). #}
