{# Database backup status. Included by platform-managing-container.html. READ-ONLY, on purpose. There is no "back up now" button and no "restore" button: a restore is destructive and irreversible, and the distance between a web page and `docs/RUNBOOK.md` §6 is the only thing standing between a mis-click and an outage. What this card exists to do is answer "are we backed up?" without anybody running `oc get cronjob` — because a nightly job that silently stopped working is the normal way backups fail, and nothing else in the portal would ever mention it. Fed by /api/backups, which re-checks admin access itself; this card sitting on an admin page is a convenience, never the permission. #}
